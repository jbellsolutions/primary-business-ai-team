# Website post

Serves #43 (articles and posts with images: Chris writes, the assistant posts) and #44 (blog posts: how often is open, so this skill sets no schedule).

## Inputs
- Chris's text, as he wrote or dictated it. Or the article outline from research-to-post with his text filled in.
- Which website it is for (the business website or the project website, names in `owner.md`). If the text doesn't say, ask Chris. The project website is part of a project the business manages, not Chris's own company.
- `owner.md`: categories or required fields if listed, the funder acknowledgement line if the project has one, and who manages each site.
- Images Chris supplies, the social image from the workshop folder, or a Canva design Adrielle makes. Any chart comes from honest-chart with Chris's signed checklist.
- SOP 15 (Create and post a workshop on the website) and SOP 26 (Website upkeep) for the draft, preview and yes pattern.

## Steps
1. **Keep Chris's words.** Fix only Australian spelling, typos, punctuation, headings and layout. Don't change a number, unit, product, rate or technical statement. Anything unclear goes on a question list, not into the text.
2. **Show what changed.** List every edit as original → edit → reason, so Chris can see nothing technical moved.
3. **Add the WordPress parts:**
   - title, a one-line summary for the excerpt, a short intro and headings;
   - a short slug in lower case with hyphens, and a one-sentence search description;
   - category and tags from the site's existing ones. Adrielle reads them in WordPress; if the required fields aren't known, `check with Chris`.
4. **Images.** For each: file name, caption, alt text that says what the picture shows, and the OK needed (photos of people). No image is added without a source.
5. **Links.** List every link with its target. Adrielle tests each one. Don't link to a page you haven't seen.
6. **Funder line.** An article for the project website is the project's material, so this check always applies to it. If `owner.md` says the project needs an acknowledgement, put it at the end exactly as written. If it doesn't say, write `FUNDER LINE: ask Chris`.
7. **Paste-ready block** in this order: Title · Excerpt · Body · Image table · Category and tags · Link list · Questions for Chris.
8. **Adrielle's path** (the draft, preview and yes pattern in SOP 15 and 26):
   - save as a draft in WordPress under her own user, and preview on laptop and phone;
   - send Chris the preview link on Teams and wait for his yes, then publish;
   - use the normal post editor. Don't drag blocks on Elementor pages, and don't touch themes, menus, plugins or settings.
9. **After it is live,** offer a farmer-post that points to the live article, and the post-log line. Check the live page and every link first.

## Output
The paste-ready block, the edits list and any questions. After publishing, a farmer-post draft that links to it.

## Done when
Chris's text is unchanged in substance, every image has alt text, every link is listed, and Adrielle has what she needs to save a draft. Publishing happens only after Chris's yes.

## Never
- Log in to WordPress, publish, or edit a live page.
- Change what Chris's text says, or add a claim, number or recommendation.
- Create or edit event pages (Workshops & Travel drafts those under SOP 15).
- Change a theme, plugin, menu, setting, hosting or domain, or delete anything. Old pages are archived by a person.
- Name a funder from memory.
