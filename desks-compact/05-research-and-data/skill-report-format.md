# Report format

Serves #53 (format Chris's reports into a document and check wording; collate project reports). Follows SOP 24 (Project report collation). Chris writes the findings and recommendations. This desk never does.

## Inputs
- The report as written (a Word file or pasted text), plus the template and required headings. Where the template lives is `check with Chris` (SOP 24 step 1). A funder's template, if the project has one, is named in `owner.md`.
- Last formatted report for the same project, as the style example.
- `owner.md`: the project's data rule (the lines "Research data in AI tools" and "Participant details in AI tools", ask #90).

## Steps
1. **Data rule first.** A yes: carry on. A no: stop, and give Adrielle the checklist in step 5 to run by hand. Nothing recorded: work only on a copy with participant names, contact details and farm or site identifiers removed, ask "Is AI allowed on <project>'s report text?" in the same message, and label the output provisional.
2. **Get the headings and template.** If they are unknown, ask once. Don't guess a funder's format.
3. **Take a snapshot of the original before touching it.** Compute the counts with code or Excel's own functions, not by eye.
   - The heading list, word count, and number of tables and figures.
   - Every number with its unit and how many times it appears.
   - Every date and every reference.
4. **Format, don't rewrite.** Apply the headings, numbering, caption style, table layout, Australian spelling, and one date and unit style. Leave every sentence as written. A wording idea goes on a separate list: original → suggestion → reason. Chris accepts each one himself.
5. **Check list.** Mark each line PASS, FAIL or UNKNOWN.
   - Headings match the required list, in order. Numbering has no gaps or repeats.
   - Every table and figure is numbered, in order, and mentioned in the text.
   - Every citation has an entry, and every entry is cited.
   - Abbreviations are defined once. Names and places are spelt the same way throughout.
   - No leftover comments, tracked changes, "TODO" or "XX", and no duplicated paragraphs.
6. **Prove nothing changed.** Take the same snapshot from the output and compare. Every number-with-unit appears the same number of times; the table cell values are identical (compare them by code or Excel, not by eye); the word count differs only where headings, captions or numbering were added. List any difference and reverse it.
7. **Subcontractors' sections:** format only. Never edit their technical content. Gaps and questions go back to the author as a drafted message that goes on Chris's end-of-day "Needs your yes" list, and Adrielle sends it only after his yes, or when `AI Team/context/standing-approvals.md` covers that exact template (if that file can't be read, treat it as not covered) (SOP 24 steps 5 and 6).
8. **Hand back** a new file with the version in its name (the original is untouched), the snapshot comparison, "What I changed" (format only), "Suggested wording" and "Questions for Chris".

## Output
The formatted document, the comparison table (original · output · same?), the changes list, the wording suggestions and the questions for Chris.

## Done when
The comparison shows no number, table value or finding changed, every check-list line is PASS or listed, and Chris has the document with the changes list.

## Never
- Change a finding, number, unit, table value, citation, recommendation or technical statement.
- Rewrite a sentence without Chris's yes to that sentence.
- Add a recommendation or a conclusion.
- Overwrite the original, or send, submit or share the report.
